# Подключения билетных сервисов и касс

Подключения находятся в «Настройки компании → Интеграции → Билетные сервисы и кассы». Доступны владельцу и администратору компании без ограничений должности. Глобальная роль пользователя этого доступа не даёт. Настройки доступны независимо от тарифа и включения билетного модуля.

## Фактически работающие возможности

| Сервис | Проверка подключения | Предпросмотр | Пока недоступно |
| --- | --- | --- | --- |
| Ticketscloud | Чтение первой страницы заказов | Заказы, количество билетов, исходные статусы, суммы и сведения о событии из `refs` | Каталог gRPC, доступные места, резервирование, продажа и возврат во внешнем пуле |
| Эвотор | Чтение списка магазинов | Облачные документы `SELL` и `PAYBACK` выбранного магазина | Команды терминалу, эквайринг, фискализация и автоматическая запись оплат в CRM |
| Красбилет | Нет | Нет | Требуются партнёрская документация и условия доступа к API |

Сохранение токена не обращается к провайдеру. «Проверить чтение» и «Показать предпросмотр» выполняют только GET-запросы после явного нажатия. Автоматических фоновых запросов к провайдерам нет.

Предпросмотр ничего не импортирует: не создаёт клиентов, программы, сеансы, продажи, платежи или записи финансового журнала и не изменяет вместимость. Внешние программы остаются недоступными для продажи, пока не реализовано подтверждённое бронирование в общем пуле.

Статус заказа Ticketscloud не означает поступление денег компании. Сумма чека Эвотора также не подтверждает выплату агрегатора или банковское зачисление. Оплата покупателем, перечисление агрегатором и оказание услуги остаются разными фактами.

## Настройка сервера

Обязательная переменная окружения `PARTYCRM_PROVIDER_ENCRYPTION_KEY`: отдельный случайный ключ длиной 32 байта, представленный 64 шестнадцатеричными символами или стандартным base64 с `=`. Не используйте пользовательский пароль, токен провайдера или публичную переменную `NEXT_PUBLIC_*`.

Ключ задаётся только на сервере. Без него сохранение/проверка токенов недоступны; общая страница настроек продолжает работать. Генерация значения возможна штатным криптографическим генератором при настройке сервера. Значение не должно попадать в Git, логи или клиентский код.

Токены хранятся в отдельной коллекции `ticketProviderConnections` с AES-256-GCM, случайным IV и дополнительной аутентификацией компании и провайдера. Поле credential исключено из обычных выборок. API возвращает только признаки настройки, статус и несекретные параметры. Из браузера можно заменить либо удалить токен; прочитать сохранённое значение нельзя.

Ключ необходимо сохранять вместе с защищёнными резервными копиями. При его замене существующие токены перестанут расшифровываться: удалите подключения и введите токены заново. Автоматической ротации в этом срезе нет.

## Используемые официальные контракты

Ticketscloud: `GET https://ticketscloud.com/v2/resources/orders`, заголовок `Authorization: key <API_KEY>`, параметры `page`, `page_size`, `created_at`. Страница предпросмотра содержит до 40 заказов. Документация: [основы API](https://doc.ticketscloud.org/ru/latest/walkthrough/basics.html), [список заказов](https://doc.ticketscloud.org/ru/latest/extra/orders_list.html). Старый REST-каталог событий не используется: [актуальный каталог переведён на gRPC](https://doc.ticketscloud.org/ru/latest/walkthrough/events.html). Даты без смещения показываются как даты источника; часовой пояс события сохраняется отдельно, UTC не выдумывается.

Эвотор: `GET https://api.evotor.ru/api/v1/inventories/stores/search` и `GET /api/v1/inventories/stores/{storeUuid}/documents`, заголовок `X-Authorization` с токеном Облака Эвотор. Это не токен ОФД и не MobileCashier. Документы запрашиваются по `gtCloseDate`/`ltCloseDate` и `types=SELL,PAYBACK`. Согласно [официальному REST API](https://api.evotor.ru/docs/), доступная история документов ограничена шестью месяцами, диапазон одного запроса — месяцем. В CRM предпросмотр дополнительно ограничен семью днями и 200 документами; при обрезке показано предупреждение и предлагается сократить период. [Получение доступа к облачному API](https://developer.evotor.ru/docs/rest_getting_started_guide.html).

В интерфейсе границы периода переводятся в ISO из локальных полуночей устройства; «До» не включается. У провайдера действуют собственные правила включения пограничного времени: предпросмотр не предназначен для гарантированного потокового импорта. Нет автоматического checkpoint, дедупликации или отчёта о полной синхронизации.

## API CRM и защита транспорта

`GET /api/party/ticketing/providers` возвращает `data: { encryptionReady, providers[] }`, без внешних запросов. `POST` принимает `{ action, provider, expectedRevision, ... }`:

- `save`: `token`; для Эвотора также `storeUuid` (можно пустой, чтобы сначала получить список магазинов). Пустой token сохраняет прежний, если подключение уже есть.
- `disconnect`: удаляет сохранённый токен.
- `test`: проверяет чтение; для Эвотора возвращает безопасный список `{ id, title }` магазинов.
- `preview`: `payload: { dateFrom, dateTo, page? }`, обе даты — ISO со смещением, период до семи дней; page используется Ticketscloud.

В каждом запросе компания задаётся штатным заголовком `x-partycrm-company-id` и проверяется сервером через membership. Ревизия защищает замену подключения от устаревших вкладок. Ответы не кэшируются. Хосты и пути заданы кодом; пользовательские URL и редиректы не допускаются. Таймаут — 10 секунд, размер ответа ограничен 2 МиБ. Ошибки провайдера не передаются пользователю дословно, чтобы не раскрыть секреты или персональные данные. Контакты покупателей, штрихкоды, содержимое транзакций и адреса магазинов в предпросмотр не включаются.

Проверки в разработке используют подставной транспорт. Реальная проверка пользовательского токена и доступных разрешений выполняется пользователем после настройки сервера; без токенов реальная связь не проверялась.
