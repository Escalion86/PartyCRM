# PartyCRM Invite Registration Prefill Design

## Goal

Упростить приглашение сотрудника до одного клика, формировать production-ссылку из `DOMAIN` и заполнять регистрацию данными сотрудника из действующего приглашения.

## Flow

1. Администратор нажимает «Пригласить в систему».
2. Клиент сразу отправляет `POST /api/party/staff/:id/invite`, раскрывает панель и показывает новую ссылку.
3. API строит ссылку от `process.env.DOMAIN`; origin запроса используется только при отсутствии переменной.
4. Новый пользователь переходит на страницу приглашения и выбирает регистрацию.
5. Форма регистрации получает только `inviteToken`, сама загружает публичные данные приглашения и заполняет телефон, имя, фамилию и режим интерфейса.
6. Роль определяется приглашением: `admin` -> `company`, `performer` -> `performer`. Пользователь по-прежнему подтверждает телефон и принимает приглашение после регистрации.

## Security And Errors

- Query-параметры не считаются источником ФИО, телефона или роли.
- Полные данные регистрации выдаются только владельцу bearer-токена активного приглашения.
- Недействительное приглашение не заполняет форму и показывает существующую ошибку API.
- Телефон нельзя считать подтверждённым только из-за prefill: используется текущий звонок/SMS flow.

## Testing

- Unit-тест домена `DOMAIN`, удаления завершающего `/` и fallback origin.
- Unit-тест публичного prefill: раздельные имя/фамилия, телефон и роль.
- Статический тест потока UI: первый клик вызывает создание; регистрационная ссылка передаёт токен; форма использует prefill.
- Полный набор unit-тестов, ESLint и production build.
