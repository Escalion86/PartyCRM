# Сворачиваемые карточки интеграций PartyCRM

## Цель

Сделать раздел `Настройки компании -> Интеграции` компактнее: настройки каждой интеграции скрыты до раскрытия карточки, а состояние подключения видно без открытия блока.

## Объем изменений

- Изменить только интерфейс `CompanySettingsIntegrationsContent` и связанные с ним тесты.
- Сохранить существующие API, формы, действия подключения, проверки и ограничения тарифа.
- Не изменять серверную модель интеграций и контракты endpoint-ов.
- Не закрывать roadmap-пункты: задача является локальным UX-улучшением существующего раздела.

## Компонент карточки

`CompanyIntegrationCard` становится управляемой внутри себя сворачиваемой карточкой.

- Заголовок реализуется кнопкой на всю ширину карточки.
- Каждая карточка раскрывается независимо от остальных.
- Все карточки свернуты при первом рендере.
- Состояние раскрытия хранится локально и не сохраняется после ухода со страницы.
- Стрелка справа поворачивается при раскрытии.
- Кнопка содержит `aria-expanded` и `aria-controls`, область содержимого имеет стабильный связанный `id`.
- Вся область заголовка имеет `cursor-pointer` и доступна с клавиатуры как обычная кнопка.

Визуальный стиль остается PartyCRM: белый фон, голубая граница, крупное скругление, спокойный hover-фон и текущая типографика.

## Индикатор состояния

Слева от названия отображается компактная цветная точка с визуальным ореолом:

- зеленая: интеграция подключена;
- серая: интеграция не подключена;
- янтарная: интеграция требует внимания или недоступна по тарифу;
- во время загрузки статуса точка использует нейтральное состояние с анимацией пульсации.

Точка получает текстовое пояснение через доступное имя или скрытый текст, чтобы состояние не передавалось только цветом.

## Правила определения состояния

- `Входящие заявки API / Tilda`: подключено, когда прием заявок включен и существует хотя бы один активный API-ключ.
- `Avito`: подключено, когда нормализованный статус API равен `connected`; включенное состояние с другим статусом считается требующим внимания.
- `VK`: подключено, когда нормализованный статус API равен `connected`; включенное состояние с другим статусом считается требующим внимания.
- `Novofon`: подключено, когда нормализованный статус API равен `connected`; тарифная блокировка имеет приоритет и показывает янтарное состояние.
- `AITunnel / AI`: подключено, когда сохранен непустой ключ `aitunnelKey`; тарифная блокировка имеет приоритет и показывает янтарное состояние.
- Ошибка загрузки общего статуса не делает интеграцию подключенной; карточки остаются в нейтральном или предупреждающем состоянии на основании доступных локальных настроек.

## Заблокированные карточки

Карточка, недоступная по тарифу, остается сворачиваемой. В заголовке показывается янтарный индикатор, а после раскрытия сохраняется существующее сообщение об ограничении. Интерактивные элементы содержимого остаются отключенными существующим механизмом `pointer-events` и `disabled`.

## Mobile-first

- Название и описание занимают доступную ширину и корректно переносятся.
- Индикатор и стрелка не сжимаются.
- Заголовок имеет достаточную высоту для касания.
- Содержимое использует существующие responsive-сетки без изменений.

## Тестирование

Добавить тесты поведения карточки:

- содержимое скрыто по умолчанию;
- нажатие раскрывает и повторное нажатие сворачивает содержимое;
- `aria-expanded` соответствует состоянию;
- индикатор получает корректное состояние для подключенной, отключенной, предупреждающей и загружаемой интеграции;
- правила вычисления состояния для API/Tilda и провайдеров проверяются отдельно как чистая функция, если текущая тестовая инфраструктура не поддерживает рендер React-компонента.

После реализации выполнить точечный ESLint измененных файлов и доступные тесты раздела настроек компании.
