# Доступ к настройкам компании по тарифу

## Цель

Сделать подразделы `Настройки компании` доступными владельцу и администратору компании независимо от глобальной роли PartyUser, сохранив тарифное ограничение только для документов.

## Матрица доступа

| Подраздел | Owner/Admin компании | Performer | Тарифное ограничение |
| --- | --- | --- | --- |
| Общие | доступен | недоступен | нет |
| Интеграции | доступен | недоступен | нет |
| Списки | доступен | недоступен | нет |
| Уведомления | доступен | недоступен | нет |
| Документы | доступен | недоступен | `allowDocuments` |
| Тарифы | доступен | недоступен | нет |

Глобальные роли `admin` и `dev` не заменяют membership компании. Для входа в настройки пользователь должен иметь активную роль `owner` или `admin` в выбранной компании.

## Поведение меню

- Владелец и администратор видят все шесть подразделов.
- Жёлтые звёзды у `Интеграции`, `Уведомления`, `Документы` и `Тарифы` удаляются: они больше не обозначают глобальный доступ `admin/dev`.
- Пункт `Документы` остаётся видимым при любом тарифе.
- При отсутствии `allowDocuments` страница показывает существующее сообщение о недоступности функции и предлагает перейти во вкладку `Тарифы`.

## Route guard

- Прямой URL любого подраздела разрешён только активному `owner/admin` выбранной компании.
- `performer` и пользователь без membership перенаправляются из настроек компании.
- Route guard не ограничивает `Интеграции`, `Уведомления` и `Тарифы` по тарифу.
- Тарифная проверка `Документов` остаётся внутри содержимого страницы и API-фильтра настроек.

## Данные тарифа

Новые поля тарифа не добавляются. Используется существующий `allowDocuments`. Флаг `allowIntegrations` не вводится.

## Тестирование

- Unit-тесты матрицы вкладок для `owner`, `admin`, `performer` и пользователя без management membership.
- Unit-тест, что все подразделы видимы owner/admin и не имеют access-marker.
- Проверка существующих тестов `partyTariffAccess` и `companySettings`.
- Точечный ESLint и production build.
